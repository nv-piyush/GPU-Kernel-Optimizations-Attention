\begin{abstract}
% ─────────────────────────────────────────────────────────────────────────────

Scaled dot-product attention is the computational core of Transformer-based
models, with runtime complexity that grows quadratically with sequence length
and performance frequently constrained by GPU memory bandwidth rather than
floating-point throughput. This paper addresses the following research
question: \textit{under what workload configurations do shared-memory tiling
and kernel fusion improve GPU kernel performance for scaled dot-product
attention, and what hardware-level mechanisms explain those effects?}
We implement five CUDA kernel variants on an NVIDIA RTX~5060~Ti and evaluate
them across 32 workload configurations spanning batch sizes 1--32, sequence
lengths 128--1024, and head dimensions 64 and 128. Timing is reported as
mean~$\pm$~standard deviation over 100 iterations. Nsight Compute hardware
profiling provides counter-level explanation for all observed performance
differences. Key findings are: (1)~shared-memory tiling reduces warp stall
cycles from 172 to 66 per instruction and delivers
1.09$\times$--2.14$\times$ end-to-end speedup; (2)~correcting the softmax
kernel launch grid from 2 blocks to $N \times B$ blocks resolves severe SM
underutilization and achieves up to 5.12$\times$ speedup, demonstrating that
launch configuration can outweigh algorithmic optimization; and (3)~naive
kernel fusion regresses by up to 3.37$\times$ at large workloads because it
sacrifices tiling and causes L2 cache overflow, confirming that high GPU
occupancy is insufficient for performance when memory access patterns are
poor. Roofline analysis places all variants in the memory-bound regime with
arithmetic intensities of 0.3--8 FLOPs/Byte against a ridge point of
49.3 FLOPs/Byte.

\end{abstract}

\section{Introduction}
% ─────────────────────────────────────────────────────────────────────────────

\subsection{Context and Background}

Transformer-based architectures~\cite{vaswani2017attention} underpin modern
large language models and sequence-to-sequence systems. Their core operation,
\textit{scaled dot-product attention}, computes a weighted combination of
value vectors based on query-key similarity scores. Given query $Q$, key $K$,
and value $V$ matrices of shape $B \times N \times d$ — where $B$ is batch
size, $N$ is sequence length, and $d$ is head dimension — attention produces:
\[
  \text{Attention}(Q,K,V)=
  \text{softmax}\!\left(\frac{QK^\top}{\sqrt{d}}\right)V
\]
The intermediate score matrix $QK^\top\in\mathbb{R}^{N\times N}$ requires
$O(N^2)$ memory and dominates both arithmetic and memory costs. The operation
is \textit{memory-intensive}: the primary performance constraint is data
movement between GPU memory levels — global DRAM, L2 cache, L1 cache — rather
than floating-point computation. This is the condition of being
\textit{memory-bandwidth limited}, meaning the GPU's arithmetic units sit idle
waiting on data.

Research has established that attention on GPUs is frequently
memory-bandwidth limited~\cite{dao2022flashattention,wang2019characterizing}.
Two classical GPU optimization techniques address this:
\textit{shared-memory tiling}, which loads tiles of operands into on-chip
shared memory for reuse, and \textit{kernel fusion}, which eliminates
intermediate DRAM buffers between sequential operations. However, their
isolated effects on attention kernels under varying workload conditions are
not fully characterized in the literature.

\subsection{Problem Statement and Research Question}

While attention is known to be memory-bound, the practical effect of specific
kernel-level optimizations — under which batch sizes, sequence lengths, and
head dimensions they help, when they do not, and what hardware mechanisms
explain the difference — has not been empirically isolated in a controlled
setting. Existing work either proposes complete algorithmic redesigns such as
FlashAttention~\cite{dao2022flashattention} or performs broad workload
characterization~\cite{wang2019characterizing} without isolating individual
kernel choices.

This paper addresses the following research question:
\begin{quote}
  \textit{Under what workload configurations do shared-memory tiling and
  kernel fusion improve the performance of GPU attention kernels, and what
  hardware-level mechanisms — measurable via hardware performance counters —
  explain those effects?}
\end{quote}

\subsection{Significance of the Study}

Understanding the conditions under which specific low-level optimizations
help or hurt is practically significant for GPU systems developers: it
informs implementation choices without requiring exhaustive empirical search.
Theoretically, it provides a controlled case study of the interaction between
memory hierarchy behavior and kernel design decisions in a widely-deployed
computational primitive. Each performance observation is paired with a
hardware counter measurement (warp stall cycles, SM occupancy, memory
throughput) that explains the causal mechanism, making findings transferable
beyond the specific kernel studied.

\subsection{Scope and Organization}

This paper evaluates single-head scaled dot-product attention during inference
only (no training). The analysis is restricted to kernel-level implementation
choices; algorithmic changes such as online softmax or approximate attention
are out of scope. Section~\ref{sec:litreview} reviews related work.
Section~\ref{sec:method} describes the five implementation variants.
Section~\ref{sec:results} presents benchmark and profiling results.
Section~\ref{sec:discussion} interprets the results and discusses tradeoffs.
Section~\ref{sec:conclusion} concludes.

\section{Literature Review}
\label{sec:litreview}
% ─────────────────────────────────────────────────────────────────────────────

\subsection{Overview of Existing Research}

\textbf{Transformer attention.}
Vaswani et al.~\cite{vaswani2017attention} introduced the Transformer
architecture with multi-head self-attention. The $O(N^2)$ complexity with
respect to sequence length has motivated extensive optimization research as
context windows grow.

\textbf{IO-aware attention algorithms.}
Dao et al.~\cite{dao2022flashattention} demonstrated that standard attention
is memory-bandwidth limited and proposed FlashAttention, which restructures
computation using online softmax to fuse the $QK^\top$ and softmax operations
within shared-memory tiles, eliminating the $O(N^2)$ DRAM materialization of
the score matrix. FlashAttention-2~\cite{dao2023flashattention2} further
improves parallelism across sequence positions.

\textbf{GPU workload characterization.}
Wang et al.~\cite{wang2019characterizing} performed architectural analysis of
deep learning workloads on production GPU clusters, finding that many
operations operate near memory bandwidth limits.

\textbf{Roofline modeling.}
Williams et al.~\cite{williams2009roofline} introduced the Roofline model,
which characterizes kernel performance as a function of arithmetic intensity
(FLOPs per byte of memory traffic). Kernels below the ridge point are memory
bandwidth limited; those above are compute limited.

\textbf{Systems optimization methodology.}
Jia et al.~\cite{jia2019optimizing} advocate for systematic performance
analysis of computation graphs and study of optimization tradeoffs in
isolation, supporting the controlled experimental design used here.

\subsection{Critical Evaluation}

FlashAttention is the state-of-the-art production approach. Its tile-aware
fusion is the algorithmically correct solution to the memory-bound attention
problem, but it is a complete algorithmic redesign, not an incremental kernel
optimization. Wang et al.'s characterization is broad but does not isolate
individual kernel-level choices or explain hardware mechanisms behind
performance differences. Neither body of work provides a controlled comparison
of incremental techniques (tiling tile size, grid configuration, fusion
granularity) with hardware counter evidence isolating each effect.

\subsection{Theoretical Framework}

This study is framed by two models. The Roofline
model~\cite{williams2009roofline} predicts performance ceilings based on
arithmetic intensity and hardware limits. Amdahl's
Law~\cite{amdahl1967validity} predicts end-to-end speedup limits when only
fraction $f$ of runtime is optimized by factor $s$: the end-to-end speedup is
bounded by $1/((1-f)+f/s)$. Both models make predictions tested against
measured results.

\subsection{Research Gap and Rationale}

The specific gap addressed is the absence of controlled, hardware-counter-backed
empirical analysis isolating individual kernel-level optimization choices for
attention across varying $(B,N,d)$ configurations. This study fills that gap
by pairing each latency measurement with Nsight Compute profiling that makes
the causal mechanism explicit, enabling principled conclusions about when each
technique is warranted and directly addressing the identified literature gap
through quantitative analysis under varying workload configurations.

\section{Methodology}
\label{sec:method}
% ─────────────────────────────────────────────────────────────────────────────

\subsection{Research Design}

This study uses a controlled experimental design. A baseline CUDA
implementation serves as the control; four optimized variants are evaluated
as treatments. All variants use identical input tensors (fixed random seeds)
and the same measurement protocol. Independent variables are batch size $B$,
sequence length $N$, and head dimension $d$. Dependent variables are latency
(mean~$\pm$~std over 100 iterations) and Nsight Compute hardware performance
counters. Each variant is evaluated at all 32 combinations of
$B\in\{1,4,16,32\}$, $N\in\{128,256,512,1024\}$, $d\in\{64,128\}$.

\textbf{Relationship to optimized frameworks.} The baseline is an
intentionally naive global-memory CUDA implementation with no cuBLAS, cuDNN,
or library kernels. This is not intended to compete with production
frameworks — PyTorch's \texttt{scaled\_dot\_product\_attention} and cuDNN
apply many of the techniques studied here and substantially outperform the
baseline. The naive baseline provides a controlled starting point where each
optimization is added one at a time and its isolated effect can be measured.
Hardware counter profiling is not available for black-box library kernels.

\subsection{Implementation Variants}

\textbf{Baseline.} Three sequential global-memory CUDA kernels, each
operating exclusively on global DRAM with no shared memory:

\begin{enumerate}[noitemsep]
\item \texttt{qk\_dot\_scaled\_kernel}: one thread per $S_{b,i,j}$.
      Grid $(\lceil N/16\rceil,\lceil N/16\rceil,B)$, block $(16,16)$.
\item \texttt{softmax\_kernel}: one thread per row $S_{b,i,:}$.
      Grid $(\lceil N/256\rceil,B)$, block $(256)$.
\item \texttt{attn\_output\_kernel}: one thread per $O_{b,i,k}$.
      Grid $(\lceil d/16\rceil,\lceil N/16\rceil,B)$, block $(16,16)$.
\end{enumerate}

\textbf{Tiled QK.} Replaces kernel (1) with a shared-memory tiled variant
(tile size $T{=}16$, 2~KB shared memory per block). For each output tile,
the kernel iterates over $\lceil d/T\rceil$ tiles of $Q$ and $K$, loading
each cooperatively before computing partial dot products. Each K tile is
reused $T{=}16$ times per block, reducing global memory loads by factor $T$.

\textbf{Softmax Fixed Grid.} Retains tiled QK; changes the softmax grid
from $(\lceil N/256\rceil,B)$ to $(N,B)$ — one block per row. This raises
active blocks from 2 to 32,768 at $B{=}32$, $N{=}1024$.

\textbf{Naive Fusion.} Fuses kernels (1) and (2) into a single kernel. Each
block owns one row, computes all $N$ dot products into dynamic shared memory,
applies parallel tree-reduction softmax, and writes the result — eliminating
the intermediate $[B,N,N]$ score matrix DRAM round-trip.

\textbf{Warp Softmax.} Builds on the fixed-grid softmax by raising block
size from 1 to 32 threads (one full warp). All 32 threads stride across the
row collaboratively; five \texttt{\_\_shfl\_down\_sync} warp-shuffle steps
compute the global max and sum in $\log_2 32{=}5$ steps rather than the
$O(N)$ sequential loop. The core warp reduction is shown below.

\begin{lstlisting}[language=C,
  caption={Warp-level max reduction using shuffle instructions.}]
float local_max = -1e38f;
for (int j = threadIdx.x; j < N; j += WARP_SIZE)
    local_max = fmaxf(local_max, row[j]);
for (int offset = WARP_SIZE/2; offset > 0; offset >>= 1)
    local_max = fmaxf(local_max,
        __shfl_down_sync(FULL_MASK, local_max, offset));
float row_max = __shfl_sync(FULL_MASK, local_max, 0);
\end{lstlisting}

\subsection{Measurement Protocol}

Each configuration runs 5 warmup iterations (discarded) followed by 100
individually timed iterations using \texttt{cudaEvent}. Per-iteration timing
enables standard deviation computation. Reported latency is mean~$\pm$~std
over 100 iterations. The coefficient of variation (CV = std/mean) assesses
relative timing noise. CV is below 2\% for all $N\geq256$, confirming
100 iterations yield stable estimates and that speedup differences above
5\% are statistically meaningful. At $N{=}128$, $B{=}1$, CV reaches up to
5\% due to kernel launch overhead representing a larger fraction of the
short total runtime.

\textbf{Note on NCU output.} NCU profiling files report elevated wall-clock
binary latency ($\sim$seconds) because NCU replays each kernel 40+ passes
for counter collection. Actual kernel durations are read from the
\textit{Duration} field in each kernel's Speed-of-Light section. NCU tables
show identical Minimum, Maximum, and Average because all profiling runs use
a single kernel invocation (\texttt{--iters 1}) — with one data point, the
three statistics are necessarily equal.

\subsection{Ethical Considerations}

This study does not involve human subjects, personally identifiable data, or
sensitive materials. All workloads use synthetically generated tensors with
fixed random seeds. No IRB approval is required.

\subsection{Tiling Results}

Tiling reduces QK kernel warp stalls from 172.6 to 66.4 cycles/instruction
and kernel duration from 107.9~$\mu$s to 32.4~$\mu$s — a 3.33$\times$
speedup in isolation. End-to-end improvement is only 1.21$\times$ because
the softmax kernel (unchanged, 2-block grid) accounts for 82\% of tiled
total runtime. Amdahl's Law with softmax fraction $f{=}0.67$ and
$s{=}3.33\times$ predicts:
\[
  S = \frac{1}{(1-f)+f/s} = \frac{1}{0.33+0.20} \approx 1.25\times
\]
The observed 1.21$\times$ is consistent with this bound, confirming that
tiling improves the wrong bottleneck.

\subsection{Key Observations}

\begin{itemize}[noitemsep]
  \item Tiling consistently reduces warp stalls but is limited end-to-end
        by the unchanged softmax bottleneck (Amdahl's Law).
  \item The grid fix delivers the largest single improvement
        (up to 5.12$\times$) via a one-line configuration change.
  \item The fused kernel benefits only at $B{=}1$ where K fits in L2;
        it regresses at $B\geq4$ due to L2 overflow and warp stalls
        2.4$\times$ worse than baseline.
  \item All kernels are memory-bound; optimizations reduce bytes moved or
        improve SM utilization — none shift kernels toward the compute
        bound.
\end{itemize}

\section{Discussion}
\label{sec:discussion}
% ─────────────────────────────────────────────────────────────────────────────

\subsection{Interpretation of Results}

\textbf{Tiling and Amdahl's Law.}
Tiling correctly targets the QK kernel's memory bottleneck (warp stalls
halved, 3.33$\times$ kernel speedup) but Amdahl's Law limits end-to-end
gain: with softmax at 67\% of baseline runtime and unchanged, the ceiling
is $\sim$1.25$\times$. This confirms that profiling to identify the actual
dominant bottleneck is necessary before applying any optimization.

\textbf{Grid configuration as a first-class optimization.}
The softmax grid fix delivers up to 5.12$\times$ speedup by resolving SM
underutilization — a one-line change outperforming the more complex tiling
optimization across most configurations. Launch configuration is a
workload-dependent optimization lever that can dominate algorithmic
techniques when underutilization is the binding constraint.

\textbf{Occupancy is necessary but not sufficient.}
The fused kernel (97.77\% occupancy, 3.55\% SM Busy) versus the grid-fixed
kernel (49.45\% occupancy, 30.73\% SM Busy) demonstrates that occupancy
measures warp \textit{presence}, not warp \textit{productivity}. When all
warps stall on a saturated L2/DRAM path, additional occupancy provides no
latency hiding benefit. SM Busy is the effective metric.

\textbf{Connection to literature gap.}
This study quantifies the gap the literature had left open: which specific
kernel-level choices matter, under which configurations, and why. The finding
that launch grid configuration can outperform algorithmic tiling, and the
negative result on naive fusion with a precise hardware explanation, are
contributions not predictable from existing literature and are directly
supported by the quantitative analysis across all 32 workload configurations.

\subsection{Implications}

For GPU systems developers, the practical takeaway is: profile before
optimizing. The baseline profiling revealed that 67\% of runtime was in a
2-block softmax — a configuration error, not an algorithmic problem. Fixing
it required one line of code and delivered more speedup than shared-memory
tiling across most configurations. For the broader HPC community, the negative
result on naive fusion illustrates that fusing kernels with incompatible
memory access patterns can introduce regressions worse than the unoptimized
baseline. The correct approach — tile-aware online softmax as in
FlashAttention~\cite{dao2022flashattention} — preserves tiling while
eliminating the DRAM round-trip, but requires substantive algorithmic
restructuring.

\subsection{Limitations}

\begin{itemize}[noitemsep]
  \item \textbf{Single GPU.} Results are specific to the RTX~5060~Ti;
        different memory bandwidth and L2 capacity would shift crossover
        points.
  \item \textbf{Compilation target.} Compiling at sm\_89 rather than
        native sm\_120 may underestimate absolute performance; relative
        comparisons are internally consistent.
  \item \textbf{Scope.} Single-head inference only; multi-head attention
        and training backward passes are out of scope.
  \item \textbf{Synthetic inputs.} Fixed-seed random tensors do not
        capture sparsity patterns from real attention distributions.
\end{itemize}

\subsection{Suggestions for Future Research}

The most direct extension is tile-aware online softmax fusion: fusing
softmax within the tiled QK loop using running max and sum accumulators,
preserving K tile reuse while eliminating the $O(N^2)$ score matrix DRAM
round-trip. This addresses the incompatibility that caused the naive fusion
regression. The warp softmax variant (Phase 5) reduces per-row reduction
from $O(N)$ to $O(N/32+\log_2 32)$; profiling to confirm SM Busy improvement
over the 30.73\% baseline is a near-term goal. Compiling with CUDA 12.8+
for native sm\_120 support would enable Blackwell-specific optimizations and
quantify the compilation target limitation.

\section{Conclusion}
\label{sec:conclusion}
% ─────────────────────────────────────────────────────────────────────────────

\textbf{Summary of Main Findings.}
This paper evaluated five CUDA kernel variants for scaled dot-product
attention across 32 workload configurations with hardware counter profiling
providing causal explanations. Shared-memory tiling delivers consistent
1.09$\times$--2.14$\times$ end-to-end speedup by reducing warp stall cycles
from 172 to 66 per instruction. A corrected softmax launch grid delivers up
to 5.12$\times$ speedup by resolving SM underutilization from 2 active blocks
to 32,768. Naive kernel fusion regresses up to 3.37$\times$ at large workloads
by sacrificing tiling, producing warp stalls of 413 cycles per instruction and
L2 cache overflow. Roofline analysis confirms all variants are memory-bound
throughout.

\textbf{Research Contribution.}
The study fills the identified literature gap through controlled,
hardware-counter-backed empirical analysis of individual kernel-level
optimization choices for attention under varying $(B,N,d)$ configurations.
The finding that launch grid configuration can outperform algorithmic tiling,
and the negative result on naive fusion with a precise hardware explanation,
are contributions not predictable from existing literature.

\textbf{Closing Thoughts.}
GPU optimization requires profiling-driven bottleneck identification and
understanding of optimization interactions. High occupancy is insufficient
when memory access patterns are poor. Simple configuration fixes can
outperform complex algorithmic changes. Amdahl's Law remains the binding
constraint: optimizing a non-bottleneck yields limited system-level gain.
